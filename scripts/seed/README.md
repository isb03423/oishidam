# Docker 개발 DB 더미 데이터

`docker-dev.sql`은 현재 `backend/src/main/resources/sql/schema.sql` 및 실행 중인 PostgreSQL 17 스키마에 맞춘 SQL이다. 기존 행을 삭제하지 않고 별도 더미 회원과 연결된 데이터를 추가한다. ID는 DB가 발급하므로 기존 ID와 충돌하지 않는다. 오류가 나면 한 트랜잭션 전체를 롤백한다.

상품명·가격·판매 상태·카테고리 관계·이미지 주소는 **2026-11-19 로컬 PostgreSQL DB의 실제 카탈로그**를 조회한 스냅샷이다. 화장품 3개와 모음형 상품 27개를 제외해 상품과 이미지를 각각 1,319개 포함했다. 로컬 DB의 회원·배송지·주문·인증 정보는 복사하지 않았다. 상품명과 카테고리명은 원본 그대로이며, 설명·회원·배송지·문의 내용에도 `[더미]` 같은 표시를 넣지 않았다. 데이터의 재실행 범위는 회원 이메일과 초기 재고 이력의 처리자로 식별한다.

상품 상세 설명은 최초 수집 당시의 엔핍 상품 ID를 기준으로 대응시켰다. 원본 본문에서 확인한 구성·원재료·알레르기 유발 성분·보관 방법과 제조사 등의 정보를 SQL에 포함한다. 본문에서 식품 정보를 확인할 수 없는 상품은 상품명과 카테고리를 바탕으로 개발용 소개 문구를 사용한다. Docker 초기화에는 외부 사이트 연결이 필요 없다.

제외한 화장품은 로손 앤드바이롬앤 컴포트 루스 파우더 CL01 클리어, 멜로우 아이팔레트 3종, 글래시 밀키 톤업 BE01 밀키 아이보리다. 상품명에 모음·모둠·모듬이 있는 상품도 제외했다. 랜덤 스티커 등 사은품이 포함된 개별 식품은 유지했다. 원본 로컬 DB에서는 삭제하지 않았다.

## 실행

새 DB 볼륨에서 `docker compose up -d --build`를 실행하면 `00-schema.sql` → `10-dev-data.sql` 순서로 스키마와 데이터가 자동 입력된다. 기존 DB 볼륨이나 컨테이너 재시작에는 초기화 SQL이 실행되지 않는다. 기존 데이터를 유지하면서 추가하려면 아래 수동 실행을 사용한다.

`compose.yaml`이 있는 `oishidam` 폴더에서 실행한다. 백엔드가 테이블을 초기화한 뒤 실행해야 한다. 아래 명령은 PowerShell에서도 그대로 사용할 수 있다.

```powershell
docker compose cp scripts/seed/docker-dev.sql db:/tmp/oishidam-docker-dev.sql
docker compose exec -T db psql -U oishidam -d oishidam -X -v ON_ERROR_STOP=1 -c "SET oishidam.seed_environment = 'development';" -f /tmp/oishidam-docker-dev.sql
```

DB 이름이 `oishidam` 또는 검증용 `oishidam_seed_verify`이고, 해당 세션의 `oishidam.seed_environment` 설정이 `development`일 때만 실행된다. **운영 DB에서 실행하지 않는다.** 이 설정은 실행자의 개발 DB 확인을 위한 장치이며 운영 여부를 자동으로 판별하지 않는다.

실행 결과의 `inserted_rows`는 이번 실행의 추가 건수, `seed_rows`는 SQL에서 식별한 시드 행의 건수다. 시드 관리자가 이미 있으면 삽입을 건너뛴다. 백엔드 시작 후 이메일이 암호화된 경우 초기 재고 이력으로 시드 관리자를 확인한다. 예전 공통 상품 설명을 사용 중이고 상품명과 대표 이미지가 일치하는 시드 상품은 설명을 갱신한다. 아래 이메일 범위는 이 파일 전용으로 예약한다. 같은 이름과 부모를 가진 카테고리가 있으면 기존 카테고리를 재사용한다.

기존 주문번호 시퀀스와 같은 시간 접두사가 있으면 기존 카운터를 안전하게 증가시켜 함께 사용한다. 기존 카테고리는 재사용한다. 따라서 기존 데이터가 있는 DB의 카테고리와 시퀀스 신규 행 수는 표보다 적을 수 있다.

주문 상태는 배송 완료 2,520건이며 결제 대기·결제 실패·결제 완료·상품 준비·해외 배송·통관·국내 배송·취소 완료가 각각 210건이다. 결제 승인 중·취소 처리 중 상태는 최종 상태로 만들지 않아 자동 복구 작업이 가상 결제키를 조회하지 않도록 했다.

고정 난수로 일반 회원 1,000명의 가입일·주문 횟수·구매 시점·구매 수량을 다르게 생성한다. 미구매 고객과 소액 단건 구매, 장기 미구매, 정기 구매, 고빈도 다구매를 포함하며 총 주문은 회원별 0~87회다. 현재 AI 고객 분석에서 유효 구매 횟수가 33가지 값(최대 74회)으로 분산되고 신규·일반·우수·저활동·이탈 위험 고객이 모두 나온다. 배송비는 현재 서비스와 같은 주문당 3,000원이다.

판매 중 상품 중 24개는 실행일 기준 최근 1~24일 사이에 등록해 신상품 목록에 표시한다. 판매 중 품절 임박 상품은 재고 1~4개인 20개이며, 신상품과 베스트 첫 6개 목록에 각각 2개씩 포함한다. 판매 중 품절 상품 11개도 유지한다. 신상품에는 과거 주문이 없고, 베스트 상품의 재고 감소에는 관리자 조정 이력을 남긴다.

## 배송지와 주문 수령 정보

`addresses`에는 수령인명, 전화번호, 우편번호, 기본주소, 상세주소, 통관고유부호, 기본 배송지 여부를 모두 넣는다. 기본 배송지 라벨은 `집`, 추가 배송지는 `회사`다. 회원마다 기본 배송지는 하나만 지정한다. 주문의 수령인과 주소는 주문 테이블에 별도로 복사해 배송지 스냅샷으로 남긴다.

이름·주소·연락처는 자연스러운 형식으로 생성한 값이다. 아파트 동·호수와 사무실 층수, 5자리 우편번호, `010` 전화번호, `P`와 12자리 숫자로 된 통관고유부호를 사용한다. 실제 인물 정보나 배송·통관이 검증된 정보는 아니다.

## 후기 별점

새로 생성하는 후기에는 문구에 맞춰 1~5점을 넣는다. 강한 추천·재구매는 5점, 만족은 4점, 보통은 3점, 불만은 2점, 심한 불만은 1점이며 무작위로 정하지 않는다.

Docker 최초 초기화 시 후기 2,520건 전체에 별점이 저장된다. 1·2·3·4점은 각각 450건, 5점은 720건이며, 생성 후 별점 누락 또는 범위 오류가 있으면 전체 삽입을 롤백한다. 기존 DB에 이 SQL을 다시 실행해도 이미 입력한 별점은 변경하지 않는다.

기존 개발 DB는 먼저 별점 컬럼과 제약을 별도로 반영해야 한다. 이미 저장된 후기의 별점은 자동으로 변경하지 않는다.

## 실제 AI 리뷰 분석

현재 서비스의 `services/sentiment.py`가 사용하는 문장 분류 모델을 Docker AI 컨테이너에서 직접 로드하고, **SQL에 저장되는 리뷰 본문 2,520개 모두**를 16개 단위로 실제 추론했다. 모델 로딩과 추론 실패 시에는 중단하도록 했으며 KNU 사전 기반 대체 분석은 사용하지 않았다.

- 모델: `tabularisai/multilingual-sentiment-analysis`
- 고정 리비전: `eea032081f8d247b4303ef3565e7cec1b6f201c9`
- DB 모델명: `tabularisai/multilingual-sentiment-analysis@eea032081f8d`
- 분석 시각·모델 확률에서 나온 신뢰도·결과 라벨을 SQL에 함께 포함했다. 실행할 때 AI 모델을 다시 다운로드하거나 추론할 필요가 없다.
- 각 결과의 입력 본문이 생성 리뷰와 정확히 같은지 SQL 실행 중 확인한다. 이후 리뷰 본문을 수정하면 기존 프로젝트 트리거가 해당 감정 결과를 제거한다.

리뷰 본문은 감정 강도가 다른 28개의 구매 경험 문구를 사용하며 일부 리뷰에 상품명을 함께 넣었다. 실제 고객 리뷰나 모델 평가용 정답 데이터는 아니다. 매우 긍정·매우 부정도 실제 추론 결과이며 분류 결과를 일정 비율로 맞추지 않았다.

## 검증과 제한

동일 Docker PostgreSQL의 별도 `oishidam_seed_verify` DB에서 실행·재실행을 검증한다. FK·UNIQUE·CHECK 제약을 유지하며, 최초 실행 시 테이블별 건수·주문 금액 합계·리뷰 작성자와 배송 완료·리뷰 작성 기한·최종 주문 상태·재고 이력 연결·문의 답변 수를 SQL 내부에서 확인한다.

별도 PostgreSQL 17 컨테이너의 빈 데이터 영역에서 자동 초기화도 검증했다. 79,950건 입력, 백엔드의 스키마 재실행 후 데이터 유지, 컨테이너 재시작 후 초기화 미실행 및 데이터 유지, 기존 카테고리 재사용을 확인했다. 현재 Docker DB의 샘플 데이터도 백업 후 같은 내용으로 갱신했으며 회원 ID·비밀번호·권한·인증 토큰은 유지했다.

결제키는 실제 토스 결제로 발급된 값이 아니므로 이 주문으로 실제 결제 조회·환불을 검증할 수 없다. 리뷰 이미지는 상품 이미지 재사용이며 사용자 촬영 사진이 아니다. 외부 ImageKit 이미지 URL의 전체 접근 여부는 검증하지 않았다.
