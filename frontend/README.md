# 오이시담 프론트엔드

Vue + Vite 기반. 현재 헤더, 말차 배너, 추천 상품·신상품 영역과 개발용 mock 전환 기반이 구현되어 있습니다.

## 실행

기존 node_modules가 있으면 추가 설치 없이 `npm run dev`로 실행합니다. 새 환경에서는 먼저 `npm install`을 실행합니다. 운영 빌드는 `npm run build`, 확인은 `npm run preview`입니다.

## Mock 사용

`npm run dev`로 실행하면 오른쪽 아래 **개발 도구 · MOCK** 버튼이 표시됩니다.

- **Mock 인증 사용**: 켜면 가상 인증, 끄면 백엔드 인증 API를 사용합니다. 선택은 이 브라우저의 localStorage에 저장됩니다.
- **응답 상황**: 정상, 빈 목록, 서버 오류(503)를 확인합니다. 상황 선택은 새로고침 시 정상으로 돌아갑니다.
- **가상 상품 응답 확인**: 홈과 개발 패널은 개발용 상품 데이터를 사용합니다. 응답 상황 선택이 두 곳에 적용됩니다.
- 전환 전에 진행 중이던 요청은 이전 결과를 반환할 수 있으므로 화면에서 재조회하거나 새로고침합니다. 개발 패널은 이전 요청 결과를 무시합니다.
- 운영 빌드에는 개발 패널과 mock 응답 코드가 포함되지 않습니다. 개발 모드는 인증 수단이 아닙니다.
- 실서버 오류를 mock 데이터로 자동 대체하지 않습니다. 아직 없는 mock API는 501 오류를 반환합니다.

### 백엔드 연결

`npm run dev`는 `.env.development`의 `http://192.168.0.204:8080/api`로 회원가입, 로그인, 로그아웃 Axios 요청을 보냅니다. 브라우저에 Mock 사용 설정을 저장해 둔 경우 개발 도구에서 **Mock 인증 사용**을 끕니다.

개인 개발 환경에서 다른 주소를 쓰려면 `.env.example`을 `.env.development.local`로 복사하고 `VITE_API_BASE_URL`을 변경한 뒤 개발 서버를 재시작합니다. 백엔드에서 프론트엔드 출처의 CORS를 허용해야 합니다. `VITE_` 변수는 브라우저에 공개되므로 비밀키를 넣지 않습니다.

API 주소가 없는데 mock을 끄면 `API_BASE_URL_MISSING` 오류를 표시합니다. 운영 빌드도 이 주소를 설정한 뒤 빌드해야 합니다.

## 임시 API 규약

백엔드 API 명세가 없으므로 다음 경로와 응답은 **프론트엔드 개발용 임시 규약**입니다. 백엔드 확정 후 services에서 맞춥니다.

| 호출 | 응답 |
| --- | --- |
| GET /categories | `{ items }` |
| GET /products | `{ items, total, page, size }` |
| GET /products/:id | 상품 상세 객체 (미존재 시 404) |

상품 목록 조건: `keyword`, `category_id`, `sort` (`new`, `price_asc`, `price_desc`), `page`, `size` (1~100). 베스트 정렬 집계 기준은 아직 미정입니다.

상품에 `variants`를 포함하며 SKU별 가격·재고를 유지합니다. `min_price`는 활성 SKU 최저가, `is_sold_out`은 활성 SKU에 구매 가능한 재고가 없는 경우입니다. ID는 DB bigint를 안전하게 전달하도록 문자열을 사용합니다. 이미지 배열은 비어 있으며 실제 상품 사진은 추후 추가합니다.

공통 요청은 `src/services/api.js`, 상품 서비스는 `src/services/catalog.js`, 가상 데이터는 `src/mocks/`, 개발 설정은 `src/config/development.js`에서 관리합니다. 회원 비밀번호 해시·갱신 토큰 등 서버 전용 데이터는 mock 응답에 넣지 않습니다.

## 이후 구현 범위와 확인 사항

장바구니, 주문·결제, 리뷰, 문의, 관리자 및 AI 분석은 아직 구현하지 않았습니다. 로그인과 회원가입은 아래 개발용 mock 흐름까지 구현했습니다. 화면별 구현 시 해당 mock을 추가합니다. 카카오 로그인과 결제사 테스트 연동은 로컬 가상 응답과 별개로 서버 연동이 필요합니다.

기능 정의서와 DB 설계에서 확인할 사항:

- 헤더의 찜 버튼에 대응하는 화면·기능 정의와 DB 테이블이 없습니다. 구현 범위를 확정해야 합니다.
- AI 추천, 고객 세그먼트, 재구매율·유지율, 감정 분석은 상세 FR과 계산·응답 규칙이 필요합니다. 기존 테이블에서 파생 계산할 수 있으므로 별도 테이블을 임의로 추가하지 않습니다.
- 리뷰 별점, 가입 필수 필드, 기본 배송지 삭제, 배송비, 베스트 기준, 결제사와 문서의 제안 상태 전이·재고 정책은 확정이 필요합니다.
- 감정 분석 대기와 실패를 모두 NULL로 표현하면 두 상태를 구분할 수 없습니다. 구분 UI가 필요하면 별도 분석 상태가 필요합니다.
- 화면 디자인과 실제 상품 자료는 아직 제공되지 않았습니다. 임시 상품 6개와 카테고리 3개를 제공합니다.

## 홈 상품 카드

- PICKS FOR YOU(추천 상품), JUST ARRIVED(신상품)를 각각 3개씩 표시합니다. PC는 좌우, 태블릿은 세로, 작은 모바일은 섹션별 가로 스크롤입니다.
- `src/components/product/ProductCard.vue`는 이미지·하트·판매 가격을 표시하고, `ProductSection.vue`는 제목·3개 카드·로딩·빈 목록·오류를 담당합니다.
- 화면 전체는 흰색, 상품 이미지 영역은 #f4f2f2입니다. 실제 제품 사진은 아직 없어 이미지 준비 중으로 표시합니다. 투명 배경 제품 이미지는 `images: [{ url, alt_text, is_primary }]` 형태로 연결합니다. 서버의 storage_key는 API에서 접근 가능한 url로 변환해야 합니다.
- GET /recommendations는 임시 API로 `{ items, source: 'DEFAULT' }`를 반환합니다. 현재 기본 샘플 추천이며 AI 개인화가 아닙니다.
- 할인 기능은 사용하지 않으며 판매 가격만 표시합니다. PC에서는 왼쪽 신상품, 오른쪽 추천 상품 순서입니다.
- 하트는 HomeView에서 공유하는 임시 선택 상태입니다. 새로고침 시 초기화되며 회원별 찜 저장·로그인 검증은 아직 연동하지 않았습니다. 상품 상세 이동도 아직 연결하지 않았습니다.

## 로그인 (/login)

- 프로젝트 로고, 이메일·비밀번호 필수 입력, 비밀번호 표시 전환, 로그인 상태 유지, 카카오 버튼을 구현했습니다. 네이버·구글 로그인은 제공하지 않습니다.
- Mock 모드의 테스트 계정은 `demo@oishidam.test` / `Oishi1234!`입니다. 잘못된 계정은 401, 개발 도구의 오류 시나리오는 503을 반환합니다.
- 카카오 버튼은 Mock 모드에서 가상 카카오 회원으로 로그인합니다. 실제 카카오 계정 인증이나 OAuth 동의는 수행하지 않습니다. Mock을 끄면 서버 연동 준비 안내를 표시합니다.
- 성공 시 홈으로 이동하고 헤더에 이름·로그아웃 버튼을 표시합니다. 로그인 상태 유지는 mock 프로필을 localStorage에 최대 7일 보관하며, 미선택 시 sessionStorage를 사용합니다. 비밀번호는 저장하지 않습니다. 이 프로필은 서버 권한 검증에 사용할 수 없습니다.
- Mock/API 전환 시 프로필을 초기화하고 진행 중인 로그인 요청을 취소합니다. 실제 회원 인증은 API/JWT 갱신 정책 확정 후 연결해야 합니다. 서버 전용 비밀키는 프론트엔드에 넣지 않습니다.
- 실제 인증 요청은 `POST /auth/signup` (email, password, passwordConfirm, name 및 선택 입력 phone, birthYear, gender), `POST /auth/login` (email, password), `POST /auth/logout` (Bearer 액세스 토큰과 본문의 refreshToken)을 사용합니다. 토큰은 메모리에 보관하며 새로고침 시 다시 로그인해야 합니다.
- 비밀번호 찾기는 아직 준비 중 안내를 표시합니다. 회원가입은 `/signup`에서 이메일·비밀번호·이름과 필수 약관 동의로 진행할 수 있으며, 휴대폰 번호는 선택입니다. 개발용 mock 가입 정보는 브라우저를 새로고침하면 초기화됩니다.
